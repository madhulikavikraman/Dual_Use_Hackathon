VoiceFlare team guide

How to set it up, what every screen does, how to run the demo, and what to say. Before an alert wakes a zone, VoiceFlare asks the people at its edge, shows how many phones it will wake, and calls residents with only the words a named human approved. Then it hands everyone who needs help to a person.

Watch

Zones on the Cal OES ladder. A fire model proposes changes, drawn dashed.

Ask

Sentinels at the zone's edge: "Does this match what you see?"

Slow

Edge-first calls, five at a time. The dose before any phone rings.

Hold

90 seconds before an Order. It can delay an alert, never stop one.

Hand to a person

Help registry, pickup runs, call backs, and a ledger of every decision.

Set up the demo laptop

About 10 minutes. You need Node 20.9 or newer and an Anthropic API key. Supabase and Retell are optional; without them the app keeps data in a local file and calls ring the browser phone.

  1. Get the code on our branch.

    git clone https://github.com/madhulikavikraman/Dual_Use_Hackathon
cd Dual_Use_Hackathon
git checkout AB_dev
npm install

  2. Add your keys. Copy the example file and set ANTHROPIC_API_KEY at minimum.

    cp .env.example .env.local

  3. Run the production build. It is faster than dev mode and has no hot-reload surprises on stage.

    npm run build
npm start            # http://localhost:3000

  4. Load the scenario. Westside Fire is the demo path. The reset also warms up the agent so the first call is quick. Run it again a minute before the demo.

    npm run seed         # or: npm run seed usc | altadena

  5. Give the phones an HTTPS address. Phone browsers allow the microphone (and location) only on HTTPS pages. Start a tunnel, paste its URL into APP_BASE_URL in .env.local, set DESK_PASSWORD so strangers with the URL cannot open the board, and restart.

    npx cloudflared tunnel --url http://localhost:3000

    Using Retell? After every new tunnel URL, run npx tsx scripts/retell-setup.ts --update so its webhooks point at it.

  6. Connect the phones. Open /phones on the laptop (from the tunnel URL, so the QR codes point there). Each volunteer scans their code, taps Tap to enable sound, and keeps the screen on. /phones shows who is online.

Rehearsing without volunteers: on /demo, turn on Autopilot and the simulator answers for all six phones. Turn it off before the real run.

Booth roles

Four of us, four jobs. Agree who does what before the judges arrive, and rehearse the hand-offs once.

/board

Supervisor

  • Drives every click in the run.
  • Types a real name and a reason at every approval. That is the point of the product.
  • Keeps the hold strip and the registry visible to the room.
beside the screen

Narrator

  • Tells the story along the ladder: watch, ask, slow, hold, hand to a person.
  • Says out loud what is simulated.
  • Hands the judge Phone 5 at the start.
/phones

Phone captain

  • Six phones online, sound enabled, screens on, charged.
  • Fixes a silent phone with a reload, or switches it to Text mode.
  • With Retell: the number saved as a contact on every phone.
/evidence · /global · /adapt

Second screen and questions

  • Shows the funding evidence, the six countries and the adaptations.
  • Takes judge questions while the run continues.
  • Keeps the deck open for the pitch slot.

Driving the board

Every change of a zone's state, every send and every hold decision asks for a name and a reason. They all land in the ledger.

Approve
Accept a model proposal (a dashed zone). Check the directive text, the route and the evacuation point before you confirm. Stage 1 calls start at the edge nearest the fire.
Change state
Set a zone's Cal OES state yourself: Monitor, Watch, Warning, Order, Shelter in Place, Lifted.
Compose Order
Opens the 90-second hold. It shows the dose (how many phones it will wake) and rings the sentinels at the edges.
Hold actions
Send now, Hold once, Edit polygon, Cancel, Hand to authority. At 0:00 it sends on time: the machine can delay an alert, never stop one.
Build pickup runs
Groups registry rows into vehicles for the response team, for example "Accessible van A: 2 stops".
Registry and Ledger
Side panel tabs. The registry lists who needs a person and where they were last heard from. The ledger lists every decision and every refusal.
Ask the board
Read-only questions about the live board, answered by Claude. It cannot change anything.
Scenario and Tour
In the header. Scenario switches the whole board (asks to confirm). Tour starts the one-minute walkthrough.

Play the full fire

/board?autoplay=1 · button on /board and /demo

One click plays the whole run on the real board, with captions that light up each rung of the ladder. Pause, skip, 2x, exit. Use it as the booth's attract loop and as the fallback when phones fail. Decisions it makes are labeled "Autoplay supervisor (simulated)" and never count as human decisions.

The pool line

/adapt · /adapt?pool=auto

The judge's example. The same ladder in seconds: a swimmer still under water, a poolside speaker and every phone in the house asked "Are you at the pool?", then the neighbor and the emergency number. Only a person can stand it down. Fire is the loudest emergency; drowning is the quietest.

Landing today

Live location to a helper at the door

Retell call → /l/<token> → registry → Send helper → /helper/<token>
  1. A person who needs help is asked on the call: "Can I text you a link that shares your phone's live location with the response team? It stays on only until help reaches you."
  2. On a yes, their words and the call are stored with the consent, and the link goes out by text (simulated until Twilio keys are set; demo phones get it on screen).
  3. They tap it and allow location. Their GPS streams to the database; the board shows a live pin with its accuracy, and the registry row says "Live GPS".
  4. The supervisor clicks Send helper (name and reason). The helper gets a page with the live spot, Navigate, Call, and En route / Arrived / Person reached.
  5. Sharing stops when the person is reached, when they tap Stop, or after 4 hours. Exact locations never appear in public feeds.

A phone call cannot carry GPS by itself, which is why the link exists. In the room, volunteer phones share their real position, so expect the pin to appear at the venue, not in Culver City. Say so.

What the agent never does

The most common judge question is "what if the AI says something wrong?" These are hard limits in the code, and every refusal is logged.

  • Changes a zone's state, or sends or cancels an alert.
  • Says anyone is safe.
  • Gives an ETA ("How long until the fire gets here?" is refused and flagged for a person).
  • Tells a caller where another person is.
  • Reads any instruction except the one a named human approved for the caller's zone.
  • Treats no answer as an all-clear. Silence means a retry, a linked contact, or a door-knock team.

It speaks English, Spanish, Korean, Mandarin, Hindi, French, Armenian and Tagalog, and opens every call with the verification phrase and the call-back number so residents can tell it from a scam.

Say this, avoid that

Say

  • "Every resident is synthetic except the phones in this room. Every broadcast is simulated; nothing reaches a real alert system."
  • On the Norte Fire: "The fire status is live from CAL FIRE. The zones and residents are simulated, and real orders come from OCFA."
  • "The model only proposes. A named person decides, and the ledger shows who and why."
  • "The machine can delay an alert by 90 seconds. It can never stop one."

Avoid

  • Naming any alerting vendor.
  • Saying LA County dropped its alert vendor. It paused the service in January 2025, resumed it, and later moved evacuation alerts to a state-managed system.
  • Saying a Pimpri-Chinchwad library lost historic books. The floods are real; no report of that loss was found.
  • Promising times or safety in your own words. The product refuses to, so we should too.

When something fails

ProblemDo this
A phone does not ringCheck /phones shows it online. Reload the phone page and tap Tap to enable sound. A call rings for 25 s, then retries once 30 s later.
Speech recognition failsSwitch that phone to Text mode. The call works the same.
A Retell call failsIt falls back to the browser phone by itself; a "transport" card on the board says so.
The first call is slowThe agent warms up after each reset. Run npm run seed again a minute before the demo.
No volunteersAutopilot on /demo and narrate from the call strip, or Play the full fire once it lands.
Anything stucknpm run seed resets the run in a second. The twist log is kept.
